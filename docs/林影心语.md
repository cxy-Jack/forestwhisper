林影心语是一个怎么样的的web平台？我们需求什么？服务哪些人群？

林影心语是一个心理支持型 Web 平台，主要的服务对象包括两类人，接纳已被心理问题困扰或需要专业引导的用户，以及没有到"问题"程度、只是情绪低落、压力大、感到孤独的普通用户

平台不替代医疗诊断与治疗，但希望在 **专业心理服务之前的第一公里** 先接住情绪，再提供认知工具，最后在必要时把用户转介给专业资源。

我们需求避免更多的人被困扰在自己的心理负担之中。

# 核心设计理念

无论在视觉上还是交互上，我都要确保做到 **不要让用户思考**，的低门槛水平

在视觉上使用柔和且轻盈的色彩，确保用户安心，我们会查看文献照顾不一样的人群

我们会使用科学的方式照顾大家，测评采用有信效度的量表，文章以心理学文献为据，要有可解释、可追溯，证据归档

情绪产生 → 首页 -> 被动或主动指引到其它功能 -> 心理测评自我认知 -> 书籍推荐或文章获取方法
    → 心愿墙 / 留言板表达与互助 → 数据沉淀 → 个性化推荐与持续陪伴

# 首页

我们希望让用户静下心来，常见的心理网站不是为了留住用户，而是在开屏告诉自己有多厉害，对于我们而言，我们希望接纳聆听用户，**淡化品牌的痕迹**

首页开屏即可见到，无论是心愿墙还是教程帖子都可以在首页中刷到

### 目标用户

| 用户类型 | 特征 | 核心诉求 | 对应功能 |
| --- | --- | --- | --- |

# 现状问题诊断

## 视觉风格割裂

**主色混乱，全站同时存在 6 套互不相干的颜色体系：**

| 颜色 | 出现位置 | 问题 |
| --- | --- | --- |
| `#6a1b9a` / `#8e24aa` 紫 | ArticlePage 标题、引用块、作者信息、面包屑 | 与全站蓝色主色完全冲突 |
| `#ff9776` 橙 | ArticlePage 返回按钮、LoadingAnimation 整体 | 与蓝色体系并置时视觉打架 |
| `#65dbff` 青 | ArticlePage 相关推荐卡片背景 | 高饱和青色与治愈基调不符 |
| `#2b71ea` 蓝 | Test / Meditation / Feedback / WishWall / UserPanel | 唯一正确方向，但未全局统一 |
| `#ff6b81` 粉 | WishWall 渐变按钮、评分标签 | 与蓝色渐变混用（`linear-gradient(to right, #2b71ea, #ff6b81)`）无设计依据 |
| `#f5f7fa→#c3cfe2` 灰蓝渐变 | NewHomePage / UserPanel / ArticleCategoryPage 卡片 | 通用模板感，与治愈主题无关 |

**HomeComponent 第 917 行**仍残留 `var(--primary-color, #6a1b9a)` 紫色回退值——说明首页与文章页曾共用一套紫色体系，后来其他页面改蓝色时未清理，是割裂的历史根源。

**圆角无规范：全站 15 种 border-radius 取值**（2/4/5/6/8/10/12/14/15/20/25/30/50/999/9999px），同类卡片在不同页面圆角不一致。

**字体体系混乱：**
- 艺术字体 `YouSheShaYuFeiTe` 被滥用于正文、按钮、描述文字（TestPage 5 处、FeedbackPage 3 处、ArticlePage、UserPanel、NewHomePage 均如此）。艺术字只适合品牌标题，正文使用会降低可读性并显得廉价。
- `Courier New` 等宽字体出现在正文描述中（ArticlePage 2 处、NewHomePage 1 处），应为代码误用。
- 未声明 webfont 加载策略，用户机器无该字体时回退到 Arial，中英文混排效果失控。

为什么会这样呢？

首先最大的问题是我们或许没有做分离，UI、颜色、控件全部混在一起了，我们需要做分离，这样不会经常出现之类问题，还能全局调用

## 的布局问题

| 页面 | 问题 |
| --- | --- |
| 首页 | 左侧标题区与右侧插画视觉重心失衡；「立即进入」按钮偏左；导航图标与文字间距不均；首屏下方留白过多 |
| 功能主页 | 树洞形象与右侧卡片组左右失衡；卡片间距偏紧；登录按钮与导航链接层级区分不清 |
| 测评页 | 返回按钮样式与全站不统一；分类按钮组下方留白过大；描述文字字号过小 |
| 冥想页 | 返回按钮与时间选择器间距过小；文字层级不清晰；底部留白过多 |
| 心愿墙 | **加载遮罩长时间遮挡全部内容**（体验硬伤）；卡片间距不均；标题字号偏大 |
| 留言板 | 「点击反馈」按钮与标题间距过近；搜索框样式粗糙；状态标签颜色区分度不足 |

## 性能问题

对于静态图片来说，全部使用webp格式

- 无全局设计 Token 文件：颜色、圆角、字号硬编码在各组件内，改一处要动十处。
- 无通用组件库：按钮、输入框、卡片、空状态、加载态每页各写一份。
- 接口请求散落在组件内，无统一拦截、错误码处理、Token 刷新机制。
- 空状态、加载态、错误态三态覆盖率不足（心愿墙加载遮罩即典型案例）。
- 主体代码仍为 JavaScript，与"Vue3+TS"的技术定位不符。
- 无 `prefers-reduced-motion` 全局适配（仅个别新页面有）。
- 无监控、无错误上报、无性能埋点。

另外还有安全与合规缺口

- 无危机干预机制：测评/聊天命中自伤倾向关键词时无热线引导。
- 无隐私政策与用户协议页面。
- 心愿、留言等 UGC 内容无敏感词过滤与举报入口。
- 全站缺少"本平台不能替代专业医疗诊断与治疗"的显著声明。

# 后端

我们的后端主要包含了所有全站的api，但是问题严重在于，我发现我们开始开始偏离需求或者创造多余的需求

数据库是pgsql + Redis

整体项目看下来分为3个整体，一是后端主题，二是管理员管理界面，三是前端界面

我们可以看到我们需求心愿墙、留言板如果我们需要他是可以的，但是目前我们的设计却导致数据库表开始变多

## 数据库表

首先我要说我自己，为了好处不断的为后端加码，却导致数据表臃肿难以维护，对于管理来说这种设计是不可控的，因为这个不是持续增长

抛开我多出的设计，数据库表也就分用户表、AI记录表、文章、评论这些部分

如果说我们需求心愿墙和留言板，完全可以把这2个设计成文章，该匿名的匿名，该展示的展示，还能在首页刷到

前端也不应该因此变的臃肿，我们完全可以把普通帖子、心愿墙和留言板放在一个编辑器中
